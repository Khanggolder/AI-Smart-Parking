## 3. Kiểm tra dữ liệu và bảo mật

Repository có các quy tắc `.gitignore` giúp loại trừ:

- `node_modules/`, `dist/`, `coverage/`: thư mục phụ thuộc và sản phẩm build Frontend.
- `data/`, `datasets/`, `models/`, `weights/`: dữ liệu và mô hình AI.
- `runs/`, `releases/`, `outputs/`: kết quả tạo ra trong quá trình xử lý hoặc huấn luyện.
- `*.pt`, `*.pth`, `*.onnx`, `*.ckpt`: các loại file trọng số mô hình.
- `.env`, `.env.*` (ngoại trừ `.env.example`): cấu hình môi trường có thể chứa thông tin nhạy cảm.
- `*.pem`: file khóa bảo mật.

**Kết quả kiểm tra:**

- Không phát hiện dataset ảnh lớn hoặc checkpoint mô hình trong cây file `main` được kiểm tra.
- Có cấu hình `.gitignore` để hạn chế commit nhầm dữ liệu và secret.
- Cần tiếp tục kiểm tra file được stage trước khi commit.
- Kết quả trên GitHub không xác nhận được tình trạng file ở máy cá nhân của từng thành viên.

## 5. Quy tắc phối hợp Git

Nhóm sử dụng GitHub làm nơi lưu trữ và quản lý mã nguồn.

Các nguyên tắc áp dụng:

1. Mỗi thành viên phát triển trên nhánh riêng.
2. Không push trực tiếp vào `main`.
3. Tạo commit có nội dung rõ ràng, kèm Task ID khi phù hợp.
4. Push code lên nhánh cá nhân.
5. Tạo Pull Request để review trước khi merge.
6. Không commit dataset lớn, model checkpoint, token hoặc file `.env` thật.

Đối với Frontend, nhánh đang sử dụng là `feature/frontend-khoi`.

Các Task ID `2.3.1`, `2.3.2` và `2.3.3` đã có commit và được push lên GitHub.
